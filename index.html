01

Concurrencia, paralelismo y programación distribuida

Multitarea

Capacidad de realizar varias tareas simultáneamente, frente a la restricción de la monotarea, donde las tareas se ejecutan una detrás de otra. Todos los sistemas operativos modernos (salvo los más antiguos, sencillos o limitados como MS-DOS o sistemas embebidos en Arduino) disponen de multitarea o multiproceso.

Concurrencia

Un sistema basado en un único procesador con un único núcleo es capaz de realizar multitarea mediante concurrencia. Los tiempos de CPU se distinguen entre los distintos procesos según una planificación dirigida por el sistema operativo. Si la CPU es lo suficientemente rápida, el número de procesos limitado y el planificador tiene un buen diseño, todas las tareas avanzarán a la vez (aparentemente) pese a que en un ciclo de CPU en un momento dado solo se pueda ejecutar una instrucción.

En una unidad de tiempo de computación solo avanza un proceso. La velocidad en la asignación de la CPU a los distintos procesos logra que no se perciba el cambio. Todas las tareas avanzan sin tener que esperar unas a que las otras terminen. Este tipo de computación se denomina concurrente.

Procesamiento paralelo

Los sistemas basados en varios procesadores o en procesadores de varios núcleos permiten ejecutar varias instrucciones en un único ciclo de reloj. Esta capacidad hace posible ejecutar en paralelo varias instrucciones. Los procesos se dividen en pequeñas subtareas (hilos) que se ejecutan en los diferentes núcleos, consiguiendo una reducción en los tiempos de ejecución de los procesos.

ConceptoDefinición
Procesamiento concurrenteVarios procesos se ejecutan en una misma unidad de proceso de manera alterna, provocando el avance simultáneo de los mismos y evitando la secuencialidad.
Procesamiento paraleloDivisiones de un proceso se ejecutan de manera simultánea en los diversos núcleos de ejecución de un procesador o diversos procesadores.

Conclusión: el procesamiento concurrente es responsabilidad del sistema operativo mientras que el procesamiento paralelo es una responsabilidad compartida entre el sistema operativo y el programa.

Programación distribuida

Otro de los paradigmas de la programación multiproceso. En este tipo de arquitectura, la ejecución del software se distribuye entre varios ordenadores, consiguiendo disponer de una potencia de procesamiento mucho más elevada, escalable y, normalmente, económica. Para construir un sistema distribuido se requiere una red de ordenadores entre los que distribuir el trabajo.

Se puede definir el procesamiento distribuido como aquel en el que un proceso se ejecuta en unidades de computación independientes conectadas y sincronizadas.

Mini-resumen: La concurrencia avanza tareas de forma alterna en un único núcleo; el paralelismo ejecuta varias instrucciones al mismo tiempo en varios núcleos; la distribución reparte el trabajo entre ordenadores conectados en red.

¿Qué es un proceso?

Un proceso es un programa en ejecución. Con el código ejecutable, los datos, la pila, el CP (contador de programa), el puntero de pila y otros registros.

Todos los programas se organizan como un conjunto de procesos. El sistema operativo toma la decisión de parar un proceso y arrancar otro. El proceso detenido debe restaurarse en el mismo estado antes del cambio de contexto.

Mini-resumen: Un proceso es un programa en ejecución con su propio código, datos, pila, contador de programa y registros. El SO gestiona el cambio de contexto entre procesos.

Contador de programa.

Información de planificación de la CPU como la prioridad del proceso.

Mini-resumen: El BCP es la estructura de datos del SO que guarda toda la información administrativa de un proceso: identificación, estado, registros, memoria, prioridad, contabilidad y E/S.
04

Estados de un proceso

Estados

  • En ejecución: el proceso está ejecutándose, usando el procesador.
  • Bloqueado: el proceso no puede hacer nada hasta que no ocurra un evento externo, como la finalización de una operación de E/S.
  • Listo: parado temporalmente y listo para ejecutarse cuando se le dé la oportunidad.

Transiciones entre los estados

  • En ejecución → Bloqueado: un proceso pasa de ejecución a bloqueado cuando espera la ocurrencia de un evento externo.
  • Bloqueado → Listo: un proceso pasa de bloqueado a listo cuando ocurre el evento externo que se esperaba.
  • Listo → En ejecución: un proceso pasa de listo a ejecución cuando el sistema le otorga un tiempo de CPU.
  • En ejecución → Listo: un proceso pasa de ejecución a listo cuando se le acaba el tiempo asignado por el sistema operativo.
En ejecución

Está usando el procesador.

Listo

Listo para ejecutarse cuando el SO le asigne CPU.

Bloqueado

Espera un evento externo (E/S, etc.).

Mini-resumen: Los tres estados principales son en ejecución, listo y bloqueado. Las transiciones están gobernadas por el planificador del SO y por eventos externos como operaciones de E/S.

Control de procesos en C/Linux: system(), execl() y fork()

system()

Alguna vez habremos necesitado dentro de un programa ejecutar otro programa. Para ello usaremos: system(), fork(), execl().

La función system() está en la librería stdlib.h, por lo que funciona en cualquier SO que tenga compilador de C/C++. Su formato es:

Firma de system()
int system(const char *cadena)

Devuelve -1 en caso de error, y el comando en caso positivo.

Ejemplo de programa: Listar el contenido del directorio actual y enviarlo a un fichero, abrir el gedit (o kwrite) con el fichero generado y ejecuta un comando que no existe en el intérprete de comandos de Linux.

execl()

La función system no se debe usar desde un programa con privilegios de administrador porque pudiera ser que se emplearan valores extraños para algunas variables de entorno y podrían comprometer la integridad del sistema. En este caso se usa execl().

La función execl() tiene otras 5 funciones relacionadas (que no veremos). Realiza la ejecución y terminación del proceso. Es decir, su llamada permite sustituir el proceso llamante por uno nuevo. Su formato es:

Firma de execl()
#include <unistd.h>
int execl(const char *path_y_programa, const char *arg0, ..., char *argn, (char *)NULL);

fork()

Hasta ahora hemos visto funciones que ejecutaban comandos ya sea en el intérprete de comandos o de ficheros en disco. Ahora veremos una función cuya misión es crear un proceso. Se trata de la función fork(). Su sintaxis es:

Firma de fork()
#include <unistd.h>
pid_t fork(void);
07

fork(), PID, getpid, getppid y wait

La función fork()

Al llamar a esta función se crea un nuevo proceso (proceso hijo) que es una copia exacta en código y datos del proceso que ha realizado la llamada (el proceso padre), salvo el PID y la memoria que ocupa.

Las variables del proceso hijo son una copia de las del padre, por lo que modificar una variable en uno de los procesos no se refleja en el otro (ya que tienen distintas memorias). Una vez realizada la copia, el proceso padre y el proceso hijo continúan la ejecución en el mismo punto y a partir de fork().

Valor devuelto por fork()

  • Devuelve -1 si se produce algún error en la ejecución.
  • Devuelve 0 si no se produce ningún error y nos encontramos en el proceso hijo.
  • Devuelve el PID asignado al proceso hijo si no se produce ningún error y nos encontramos en el proceso padre.

Obtener identificador de proceso o PID

getpid y getppid
pid_t getpid(void);
pid_t getppid(void);
  • getpid(): devuelve el identificador del proceso que realiza la llamada, es decir, del proceso actual.
  • getppid(): devuelve el identificador del proceso padre del proceso actual.

wait()

Se utiliza la función wait() para que el proceso padre espere la finalización del proceso hijo. Así, el proceso padre quedará bloqueado hasta que termine el hijo.

Firma de wait()
pid_t wait(int *status);

La sentencia wait(NULL) es la forma más básica de esperar a que un hijo termine.

Comunicación entre procesos: Pipes sin nombre

Pipes

Existen varias formas de comunicación entre procesos (Inter-Process Communication o IPC) de Linux: pipes, colas de mensajes, semáforos y segmentos de memoria compartida. Trataremos los más simples, los pipes (tuberías en castellano).

Un pipe es una especie de falso fichero que sirve para conectar 2 procesos. Si el proceso A quiere enviar datos al proceso B, los escribe en el pipe como si fuera en un fichero de salida. El proceso B puede leer los datos sin más que leer el pipe como si se tratara de un fichero de entrada. Así, la comunicación entre procesos es parecida a la lectura y escritura en ficheros normales.

Cuando un proceso quiere leer el pipe y está vacío, tendrá que esperar (es decir, se bloqueará), hasta que algún otro proceso ponga datos en él. Igualmente, cuando un proceso intenta escribir en el pipe y está lleno, se bloqueará hasta que se vacíe.

El pipe es bidireccional, pero cada proceso lo usa en una única dirección. En este caso, el kernel gestiona la sincronización.

Creación de un pipe

Para crear un pipe se realiza una llamada a la función pipe():

Firma de pipe()
#include <unistd.h>
int pipe(int fd[2]);

Esta función solo recibe un argumento, que es un array de dos enteros: fd[0] contiene el descriptor para la lectura y fd[1] para la escritura. Si la función tiene éxito devuelve 0 y el array contendrá dos nuevos descriptores de archivos para ser usados por la tubería. Si ocurre algún error devuelve -1.

Envío y recuperación de datos del pipe

Para enviar datos al pipe se usa la función write(), y para recuperar datos del pipe se usa la función read().

Firmas de read() y write()
int read(int fd, void *buf, int count);
int write(int fd, void *buf, int count);

read() intenta leer count bytes del descriptor de fichero definido en fd, para guardarlos en el buffer buf. Devuelve el número de bytes leídos.

write() es muy similar. A buf le damos el valor de lo que queramos escribir, definimos su tamaño en count y especificamos el fichero en el que escribiremos en fd.

Regla de oro: dado que los descriptores se comparten siempre debemos estar seguros de cerrar el extremo que no nos interesa.

FIFOs con nombre

Los pipes vistos anteriormente establecían un canal de comunicación entre procesos emparentados (padre-hijo). Los FIFOs permiten comunicar procesos que no tienen que estar emparentados.

Un FIFO es como un fichero con nombre que existe en el sistema de ficheros y que pueden abrir, leer y escribir múltiples procesos. Los datos escritos se leen como en una cola, primero en entrar (FIRST IN), primero en salir (FIRST OUT); y una vez leídos no pueden ser leídos de nuevo.

Los FIFOs tienen algunas diferencias con los ficheros:

  • Una operación de escritura en un FIFO queda en espera hasta que el proceso pertinente abra el FIFO para iniciar la lectura.
  • Sólo se permite la escritura de información cuando un proceso vaya a recoger dicha información.

Formas de crear un FIFO

Hay varias formas de crear un FIFO: ejecutando el comando mkfifo desde la línea de comandos de Linux o desde un programa C usando la función mkfifo().

Comando mkfifo
mkfifo [opciones] nombreFichero

Crear un FIFO en C

Firma de mkfifo()
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
mkfifo(const char *pathname, mode_t modo);

Donde: Pathname es el nombre del dispositivo creado. Modo especifica tanto los permisos de uso y el tipo de nodo que se creará.

La función mkfifo() devuelve 0 si ha funcionado correctamente y -1 si ha habido algún error.

Ejemplo de uso: mkfifo FIFO1 crea un FIFO llamado FIFO1. Luego cat FIFO1 se queda a la espera; desde otra terminal echo "Hola FIFO" > FIFO1 envía información.

Señales y sincronización entre procesos

Para que los procesos interactúen unos con otros necesitan cierto nivel de sincronización, es decir, es necesario que haya un funcionamiento coordinado entre los procesos a la hora de ejecutar alguna tarea. Podemos utilizar señales para llevar a cabo la sincronización entre dos procesos.

Señales

Una señal es como un aviso que un proceso manda a otro proceso. La función signal() es el gestor de señales por excelencia que especifica la acción que debe realizarse cuando un proceso recibe una señal. Su formato es:

Firma de signal()
#include <signal.h>
void (*signal(int Señal, void (*Func)(int))(int);

Parámetros

  • Señal: contiene el número de señal que queremos capturar. En nuestro ejemplo pondremos SIGUSR1, que es una señal definida por el usuario para ser usada en programas de aplicación. Otra señal interesante es SIGKILL que se usa para terminar con un proceso.
  • Func: contiene la función a la que queremos que se llame. Esta función es conocida como el manejador de la señal (signal handler).

Un ejemplo de uso: signal(SIGUSR1, gestion_padre) significa que cuando el proceso (en el caso del padre) recibe una señal SIGUSR1 se realizará una llamada a la función gestion_padre().

Función kill()

Para enviar una señal usaremos la función kill():

Firma de kill()
#include <signal.h>
int kill(int pid, int señal);

Recibe dos parámetros: el PID del proceso que recibirá la señal y la señal. Por ejemplo: kill(pid_padre, SIGUSR1) envía una señal SIGUSR1 al proceso padre.

Función pause()

Cuando queremos que un proceso espere a que le llegue una señal, usamos la función pause(). Para capturar esa señal, el proceso debe haber establecido un tratamiento de la misma con la función signal().

Firma de pause()
int pause(void);

Función sleep()

La función sleep() suspende al proceso que realiza la llamada la cantidad de segundos indicada o hasta que se reciba una señal.

Firma de sleep()
#include <unistd.h>
unsigned int sleep(unsigned int seconds);

Creación de procesos en Java: Runtime y ProcessBuilder

Cada instancia de una aplicación en ejecución es un proceso. Cada proceso dispone de un conjunto de instrucciones, un estado de los registros del procesador, un espacio de memoria y un estado en lo referente a la gestión que hace de él el planificador del sistema operativo.

En esta unidad se aborda la programación de aplicaciones multiproceso como la capacidad de coordinar la ejecución de un conjunto de aplicaciones para lograr un objetivo común.

Necesidades para programar un sistema basado en la ejecución de múltiples procesos

  • Poder arrancar un proceso y hacerle llegar los parámetros de ejecución.
  • Poder quedar a la espera de que el proceso termine.
  • Poder recoger el código de finalización de ejecución para determinar si el proceso se ha ejecutado correctamente o no.
  • Poder leer los datos generados por el proceso para su tratamiento.

En Java, la creación de un proceso se puede realizar de dos maneras diferentes:

  • Utilizando la clase java.lang.Runtime.
  • Utilizando la clase java.lang.ProcessBuilder.

Runtime

Toda aplicación Java tiene una única instancia de la clase Runtime que permite que la propia aplicación interactúe con su entorno de ejecución a través del método estático getRuntime(). Este método proporciona un canal de comunicación entre la aplicación y su entorno, posibilitando la interacción con el sistema operativo a través del método exec().

El siguiente código en Java genera un proceso en Windows indicando al entorno de ejecución (al sistema operativo) que ejecuta el bloc de notas a través del programa "Notepad.exe". En este caso, la llamada se realiza sin parámetros y sin gestionar de ninguna manera el proceso generado.

Runtime básico
Runtime.getRuntime().exec("Notepad.exe");

En muchos casos, los procesos necesitan parámetros para iniciarse. El método exec puede recibir una cadena de caracteres (objeto de la clase String), y en dicha cadena, separados entre espacios, se indicarán, además del programa que quiere ejecutarse, los distintos parámetros.

Runtime con parámetros
Runtime.getRuntime().exec("Notepad.exe notas.txt");

Alternativamente, se puede crear el proceso proporcionando un array de objetos String con el nombre del programa y los parámetros.

Runtime con array String
String[] infoProceso = {"Notepad.exe", "notas.txt"};
Runtime.getRuntime().exec(infoProceso);

El siguiente nivel consiste en gestionar el proceso lanzado. Para ello, se debe obtener la referencia a la instancia de la clase Process proporcionada por el método exec. Es este objeto el que proporciona los métodos para conocer el estado de la ejecución del proceso.

Runtime con referencia Process
String[] infoProceso = {"Notepad.exe", "notas.txt"};
Process proceso = Runtime.getRuntime().exec(infoProceso);

Si se necesita esperar a que el proceso ejecutado termine y conocer el estado en que ha finalizado dicha ejecución, se puede utilizar el método waitFor. Este método suspende la ejecución del programa que ha arrancado el proceso quedando a la espera de que este termine, proporcionando además el código de finalización.

Runtime con waitFor()
String[] infoProceso = {"Notepad.exe", "notas.txt"};
Process proceso = Runtime.getRuntime().exec(infoProceso);
int codigoRetorno = proceso.waitFor();
System.out.println("Fin de la ejecución: " + codigoRetorno);

ProcessBuilder

Es similar a la clase Runtime. La creación más sencilla de un proceso se realiza con un único parámetro en el que se indica el programa a ejecutar. Es importante saber que esta construcción no supone la ejecución del proceso.

ProcessBuilder básico
new ProcessBuilder("Notepad.exe");

La ejecución del proceso se realiza a partir de la invocación al método start.

ProcessBuilder con start()
new ProcessBuilder("Notepad.exe").start();

El constructor de ProcessBuilder admite parámetros que serán entregados al proceso que se crea.

ProcessBuilder con parámetros
new ProcessBuilder("Notepad.exe", "datos.txt").start();

Clases Process y ProcessBuilder

Métodos de la clase Process

Esta clase proporciona métodos para realizar la entrada desde el proceso, obtener la salida del proceso, esperar a que el proceso se complete, comprobar el estado de salida del proceso y destruir el proceso.

MétodoMisión
InputStream getInputStream()Devuelve el flujo de entrada conectado a la salida normal del subproceso. Nos permite leer el stream de salida del subproceso, es decir, podemos leer lo que el comando que ejecutamos escribió en la consola.
int waitFor()Provoca que el proceso actual espere hasta que el subproceso representado por el objeto Process finalice. Devuelve 0 si finaliza correctamente.
InputStream getErrorStream()Devuelve el flujo de entrada conectado a la salida de error del subproceso. Nos va a permitir leer los posibles errores que se produzcan al lanzar el subproceso.
OutputStream getOutputStream()Devuelve el flujo de salida conectado a la entrada normal del subproceso. Nos va a permitir escribir en el stream de entrada del subproceso, así podemos enviar datos al subproceso que se ejecute.
void destroy()Elimina el subproceso.
int exitValue()Devuelve el valor de salida del subproceso.
boolean isAlive()Comprueba si el subproceso representado por Process está vivo.

Por defecto el proceso que se crea (o subproceso) no tiene su propia terminal o consola. Todas las operaciones de E/S serán redirigidas al proceso padre, donde se puede acceder a ellas usando los métodos getOutputStream(), getInputStream() y getErrorStream(). El proceso padre utiliza estos flujos para alimentar la entrada y obtener la salida del subproceso. En algunas plataformas se pueden producir bloqueos en el subproceso debido al tamaño de búfer limitado para los flujos de entrada y salida estándar.

Atributos de ProcessBuilder

  • Un comando. Es una lista de cadenas que representa el programa que se invoca y sus argumentos si los hay.
  • Un entorno (environment) con sus variables.
  • El directorio de trabajo. El valor por defecto es el directorio de trabajo del proceso en curso.
  • Una fuente de entrada estándar. Por defecto, el subproceso lee la entrada de una tubería. El código Java puede acceder a esta tubería a través de la secuencia de salida devuelta por Process.getOutputStream(). Sin embargo, la entrada estándar puede ser redirigida a otra fuente con redirectInput(). En este caso, Process.getOutputStream() devolverá una secuencia de salida nulo.
  • Un destino para la salida estándar y la salida de error. Por defecto, el subproceso escribe en las tuberías de la salida y el error estándar. El código Java puede acceder a estas tuberías a través de los flujos de entrada devueltos por Process.getInputStream() y Process.getErrorStream(). Igual que antes, la salida estándar y el error estándar pueden ser redirigidos a otros destinos utilizando redirectOutput() y redirectError(). En este caso, Process.getInputStream() y/o Process.getErrorStream() devuelven una secuencia de entrada nula.
  • Una propiedad redirectErrorStream. Inicialmente, esta propiedad es false, significa que la salida estándar y salida de error del subproceso se envían a dos corrientes separadas, que se pueden acceder a través de los métodos Process.getInputStream() y Process.getErrorStream().
MétodoMisión
ProcessBuilder command(String argumentos...)Define el programa que se quiere ejecutar indicando sus argumentos como una lista de cadenas separadas por comas.
List<String> command()Devuelve todos los argumentos del objeto ProcessBuilder.
Map<String, String> environment()Devuelve en una estructura Map las variables de entorno del objeto ProcessBuilder.
ProcessBuilder redirectError(File file)Redirige la salida de error estándar a un fichero.
ProcessBuilder redirectInput(File file)Establece la fuente de entrada estándar en un fichero.
ProcessBuilder redirectOutput(File file)Redirige la salida estándar a un fichero.
File directory()Devuelve el directorio de trabajo del objeto ProcessBuilder.
ProcessBuilder directory(File directorio)Establece el directorio de trabajo del objeto ProcessBuilder.

Inicio de un nuevo proceso

Básico Actividad 1.1

Actividad 1.1 — Variable compartida entre padre e hijo

Enunciado

Realiza un programa en C que cree un proceso (tendremos 2 procesos, uno padre y otro hijo). El programa definirá una variable entera y le dará el valor 6. El proceso padre incrementará dicho valor en 5 y el hijo restará 5. Se deben mostrar los valores en pantalla.

Resultado esperado:

Salida esperada
Valor inicial de la variable: 6
Variable en proceso hijo: 1
Variable en proceso padre: 11

Solución

actividad1_1.c
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>

void main(){

    pid_t pid, Hijo_pid;

    int valor_variable = 6;

    printf("Valor inicial de la variable: %d\n", valor_variable);

    pid = fork();

    if (pid == -1){ // Ha ocurrido un error
        printf("No se ha podido crear el proceso hijo...");
        exit(-1);
    }

    if (pid == 0){ // Nos encontramos en el proceso hijo

        valor_variable = valor_variable - 5;
        printf("Variable en proceso hijo: %d\n", valor_variable);
    }
    else{ // Nos encontramos en el proceso padre

        Hijo_pid = wait(NULL); // Espera a la finalización del proceso hijo

        valor_variable = valor_variable + 5;

        printf("Variable en proceso padre: %d\n", valor_variable);

    }

    exit(0);
}

Explicación

Después de fork(), padre e hijo tienen copias independientes de la variable. En el hijo, 6 - 5 = 1; en el padre, 6 + 5 = 11. La variable del hijo no modifica la del padre. Se usa wait(NULL) para que el padre no termine antes que el hijo.

Básico Actividad 1.2

Actividad 1.2 — Pipe: hijo envía mensaje al padre

Enunciado

Siguiendo el ejemplo anterior, realiza un programa en C que cree un pipe en el que el hijo envíe un mensaje al padre, es decir, la información fluya del hijo al padre.

Solución

actividad1_2.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    int fd[2];
    if (pipe(fd) == -1) { perror("pipe"); return 1; }

    pid_t pid = fork();
    if (pid == -1) { perror("fork"); return 1; }

    if (pid == 0) {                     /* HIJO: emisor */
        close(fd[0]);                   /* cierra lectura */
        const char *mensaje = "Hola desde el hijo";
        size_t longitud = strlen(mensaje);
        if (write(fd[1], mensaje, longitud) == -1) {
            perror("write");
            close(fd[1]);
            _exit(1);
        }
        close(fd[1]);
        _exit(0);
    }

    close(fd[1]);                       /* PADRE: receptor */
    char buffer[128];
    ssize_t n = read(fd[0], buffer, sizeof(buffer) - 1);
    if (n == -1) {
        perror("read");
    } else {
        buffer[n] = '\0';
        printf("Padre recibe: %s\n", buffer);
    }
    close(fd[0]);
    wait(NULL);
    return 0;
}

Explicación

pipe(fd) crea dos descriptores. El hijo cierra fd[0] y escribe en fd[1]; el padre cierra fd[1] y lee desde fd[0]. Se cierran los extremos no utilizados para evitar bloqueos y para que el canal se gestione correctamente.

Intermedio Actividad 1.3

Actividad 1.3 — Señales: hijo envía SIGUSR1 y SIGKILL al padre

Enunciado

Realiza un programa en C en donde un hijo envíe 3 señales SIGUSR1 a su padre y después envíe una señal SIGKILL para que el proceso padre termine.

Solución

actividad1_3.c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>

volatile sig_atomic_t contador = 0;

void gestion_padre(int senal) {
    (void)senal;
    contador++;
    printf("Padre: recibida señal SIGUSR1 (%d)\n", contador);
    fflush(stdout);
}

int main(void){
    signal(SIGUSR1, gestion_padre);

    pid_t pid_hijo = fork();
    if (pid_hijo == -1){
        printf("Error al crear el proceso hijo...\n");
        exit(-1);
    }

    if (pid_hijo == 0){ // HIJO
        printf("Envía primera señal...\n");
        kill(getppid(), SIGUSR1);
        sleep(1);

        printf("Envía segunda señal...\n");
        kill(getppid(), SIGUSR1);
        sleep(1);

        printf("Envía última señal... y lo matará\n");
        kill(getppid(), SIGUSR1);
        sleep(1);

        kill(getppid(), SIGKILL);
        _exit(0);
    }
    else{ // PADRE
        while(1){
            pause();
        }
    }

    return 0;
}

Explicación

El padre instala un manejador para SIGUSR1 con signal(). El hijo descubre el PID del padre con getppid() y envía tres señales SIGUSR1 separadas por sleep(1). Finalmente envía SIGKILL, que termina al proceso inmediatamente y no se puede capturar. El padre permanece en pause() esperando señales hasta que es terminado.

Conceptos clave, tarjetas y comparativas para repasar antes del examen, basados en las dos presentaciones.

Tarjetas de conceptos

¿Qué es un proceso?

Un programa en ejecución con código ejecutable, datos, pila, CP, puntero de pila y registros.

¿Qué es el BCP?

Estructura de datos estática del SO que almacena la información administrativa de un proceso.

Estados de un proceso

En ejecución, Listo y Bloqueado. Las transiciones las gestiona el planificador del SO.

¿Qué devuelve fork()?

-1 si error, 0 si es el hijo, PID del hijo si es el padre.

fd[0] y fd[1] en un pipe

fd[0] es el descriptor de lectura; fd[1] es el de escritura.

¿Qué es un FIFO?

Pipe con nombre que permite comunicación entre procesos no emparentados. First In, First Out.

Señales: SIGUSR1 y SIGKILL

SIGUSR1 es de usuario y se puede capturar. SIGKILL termina el proceso y no se puede capturar.

Runtime vs ProcessBuilder

Runtime usa exec(). ProcessBuilder usa start(). Ambos devuelven un objeto Process.

¿Qué hace waitFor()?

Suspende la ejecución del programa Java hasta que el subproceso termine y devuelve su código de salida.

Errores típicos y cómo evitarlos

Olvidar cerrar extremos del pipe

Cada proceso debe cerrar el descriptor que no usa. Si no, puede haber bloqueos o lecturas que no reciben EOF.

Creer que el hijo comparte variables con el padre

Tras fork(), cada proceso tiene su propia copia de la memoria. Modificar una variable en uno no se refleja en el otro.

Interpretar mal el retorno de fork()

0 es hijo; PID positivo es padre; -1 es error.

Intentar capturar SIGKILL

SIGKILL no se puede capturar ni ignorar.

Usar waitFor() sin leer la salida del proceso

En Java, si el subproceso produce mucha salida y no se consume, el búfer puede llenarse y bloquear.

Lanzar DIR como ejecutable independiente en Windows

DIR es comando interno de cmd.exe; usar cmd.exe /c dir.
